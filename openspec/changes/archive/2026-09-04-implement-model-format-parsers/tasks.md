## 3. GGUF parser

- [x] 3.1 Parse the fixed header: magic bytes (`"GGUF"`), version (reject unsupported versions structurally, not silently), tensor count, metadata KV count. (Supports versions 2-3; version 1's `u32` counts are not supported, a real, undocumented-until-now scope limit.)
- [x] 3.2 Parse the typed key-value metadata section (string/int8/16/32/64/uint8/16/32/64/float32/float64/bool/string/array-of-any-above), preserving every entry (recognized or not) in the returned metadata map per design.md's "unrecognized metadata preserved" decision. (Recursive array parsing is depth-limited at 8 levels against adversarial nesting -- see task 4 and the corpus's `21_deeply_nested_metadata_array.bin`.)
- [x] 3.3 Parse the tensor-info section: name, dimension count and dimensions (`Vec<u64>`), `ggml_type`, offset.
- [x] 3.4 Map each tensor's `ggml_type` to `ModelDType`/`ModelQuantizationFormat` for the supported subset (`F32`/`F16`/`Bf16`/integer types, `Q4K`/`Q5K`/`Q8`); return a structured `gguf-quantization-unsupported` error naming the type for anything else. (Real gap found and fixed along the way: `ModelQuantizationFormat` had `GgufQ4K`/`GgufQ5K` but no `GgufQ8` to pair with the already-existing `ModelDType::Q8` -- added to `magnetar-runtime/src/model.rs`, purely additive, verified against the full 1108-test magnetar-runtime suite.)
- [x] 3.5 Compute each tensor's byte range from its offset, dimensions, and dtype/quantization block size, honoring the file's declared (or default) alignment padding, with checked arithmetic throughout. (Block sizes verified against upstream `ggml-common.h`, not recalled from memory: `block_q8_0` = 34 bytes/32 elements, `block_q4_K` = 144 bytes/256 elements, `block_q5_K` = 176 bytes/256 elements.)
- [x] 3.6 Validate every computed byte range against total file length and against every other tensor's range (out-of-bounds and overlap checks, same discipline as Safetensors task 2.3/2.4). (Also validates each tensor's `offset` is itself alignment-aligned, and rejects duplicate tensor names -- two checks the original task sketch didn't anticipate but the format's own invariants require.)
- [x] 3.7 Test: a well-formed fixture using each supported dtype/quantization type parses to the expected `ModelTensorMetadata` list. (`every_supported_ggml_type_round_trips`, all 11 supported `ggml_type` values; `quantized_types_carry_quantization_metadata` for the `ModelQuantization` fields specifically.)
- [x] 3.8 Test: a fixture using an unsupported `ggml_type` (e.g. a synthetic `Q2_K`-tagged tensor) is rejected with `gguf-quantization-unsupported`, not silently mapped. (`unsupported_ggml_type_is_rejected_structurally`, using real `ggml_type` 2 = `Q4_0`.)
- [x] 3.9 Test: unrecognized metadata keys survive normalization unchanged and do not affect tensor parsing. (`unrecognized_metadata_key_is_preserved_unchanged`.)

## 4. Overflow, bounds, and panic safety (both crates)

- [x] 4.1 Audit every `u64`-from-file-bytes to `usize` narrowing in both crates; replace any bare `as` cast with `usize::try_from(..).map_err(..)`. (The only `as` casts remaining are documented-safe widening conversions -- `usize -> u64` from an already-allocated slice length -- never narrowing from untrusted data.)
- [x] 4.2 Audit every size/offset arithmetic expression in both crates; replace any unchecked `+`/`*` on untrusted values with `checked_add`/`checked_mul` and a structured overflow error.
- [x] 4.3 Build a checked-in malformed-input corpus per crate (`formats/safetensors/tests/corpus/`, `formats/gguf/tests/corpus/`): truncated headers, invalid UTF-8, invalid JSON (safetensors)/wrong magic or unsupported version (GGUF), out-of-range offsets, overlapping ranges, overflow-inducing dimensions, inconsistent counts. (20 entries for Safetensors, 22 for GGUF, generated by a script rather than hand-authored binary files, with each entry's expected failure mode traced by hand before generation, not assumed.)
- [x] 4.4 Add a corpus-replay `#[test]` per crate asserting every corpus entry returns a structured error and none panics; runs under plain `cargo test` (stable toolchain, no `cargo-fuzz` requirement). (`malformed_input_corpus_never_panics` in both crates, using `std::panic::catch_unwind` to prove no panic in addition to asserting `Err`.)
- [x] 4.5 Add a `cargo-fuzz` target per crate (`fuzz/fuzz_targets/parse.rs`) exercising the same public parse entry point the corpus test uses, documented as a local/periodic (not per-PR) fuzzing entry point given the nightly-toolchain requirement.
