## Context

`magnetar-runtime` already has a full generic Model Artifact type system (`model.rs`): `ModelManifest`, `ModelArtifactId`, `ModelArchitecture`, `ModelTensorMetadata`, `ModelDType` (including `Q4K`/`Q5K`/`Q8`), `ModelQuantization`/`ModelQuantizationFormat` (including `GgufQ4K`/`GgufQ5K`), `ModelShard`, `ModelSignature`. `ModelManifest::validate()` is real, tested, and produces `ModelArtifactRecord`. None of this is new work. What is missing is the thing that produces these values from real bytes: `formats/gguf` and `formats/safetensors` are both empty `cargo new --lib` templates, and every fixture in the workspace (including first-native E2E) supplies weights as an in-memory `BTreeMap<String, HostTensor>` that was never serialized to any byte format.

Precedent for this exact kind of extraction (a real, independent submodule crate depending on `magnetar-runtime`'s public contracts, never the reverse) is `providers/cpu`, done in `reach-architecture-freeze-1` task group 14 this same session. `providers/cpu` hit a real coupling (`HostTensor` turned out to be load-bearing on `magnetar-runtime`'s own trait signatures) that had to be resolved by importing rather than duplicating a handful of types. The equivalent risk here is smaller but analogous: check which `model.rs` types the parsers can produce directly versus which need information the file format alone does not carry.

## Goals / Non-Goals

**Goals:**
- Real Safetensors parsing: header-length-prefixed JSON header, tensor inventory (name, dtype, shape, byte range), optional string metadata map -- normalized into `magnetar-runtime`'s existing generic types.
- Real GGUF parsing: magic/version/counts, typed key-value metadata section, tensor-info section, alignment padding -- normalized into the same generic types, for the dtype/quantization subset `ModelDType`/`ModelQuantizationFormat` already model (`F32`/`F16`/`Bf16`/integer types plus `Q4K`/`Q5K`/`Q8`).
- Both parsers reject overflow, out-of-bounds/overlapping byte ranges, and absurd dimensions before sizing any allocation from them, and never panic on malformed input (fuzz target + checked-in corpus regression suite per crate).
- Zero `magnetar-runtime` dependency on either format crate (static guard, extending the existing task-16.4 check).

**Non-Goals:**
- Extending `ModelLoadingCoordinator::load()` to consume parsed bytes from inside `load()` itself (`reach-architecture-freeze-1` tasks 8.1-8.6's deeper half) -- a separate, deliberate API/lifecycle decision per that task group's own note, independent of a parser existing.
- Full GGUF quantization coverage. GGUF in the wild uses ~30 `ggml_type` quantization variants (`Q2_K`...`Q6_K`, `IQ*`, etc.); `magnetar-runtime`'s `ModelDType`/`ModelQuantizationFormat` today only model `Q4K`/`Q5K`/`Q8`. This change parses the GGUF *container* format completely (every tensor's declared type is read and validated against the file), but only *normalizes* tensors whose `ggml_type` maps to an existing `ModelDType` variant; any other declared type is a structured `gguf-quantization-unsupported` rejection, not a silent mis-mapping or a new `ModelDType` variant invented under this change's own authority.
- Sharded weight support (`reach-architecture-freeze-1` / `model-format-roadmap`'s "Sharded Weight Support" requirement). Both formats are parsed as single files; multi-shard index/manifest handling is real, separate follow-up work.
- tokenizer.json, tokenizer_config, generation_config, chat templates, adapters -- all real items in `model-format-roadmap`'s broader aspirational scope, none touched here. This change is scoped to tensor-weight parsing only.
- Sign/signature verification of parsed artifacts -- covered by `model.rs`'s existing `ModelSignature`/digest machinery once a manifest exists; this change does not add new trust logic, only produces the tensor data a caller can already run through it.

## Decisions

**Parser output shape: a tensor inventory, not a full `ModelManifest`.** A bare Safetensors file carries no architecture, model identity, license, or generation defaults -- only a tensor inventory and an optional flat string metadata map (safetensors' `__metadata__` key). A bare GGUF file carries more (its KV metadata section commonly includes `general.architecture`, `general.name`, tokenizer vocabulary, and generation hyperparameters as informal, non-standardized keys), but still not the full `ModelManifest` shape (no `ModelArtifactId`/digest -- that is assigned by whatever `ModelArtifactSource` resolution loaded these bytes, outside the parser's knowledge). Each crate therefore exposes a narrower, honest return type:
- `formats/safetensors`: `pub fn parse(bytes: &[u8]) -> Result<SafetensorsArtifact, SafetensorsError>` where `SafetensorsArtifact { tensors: Vec<ModelTensorMetadata>, metadata: BTreeMap<String, String> }`.
- `formats/gguf`: `pub fn parse(bytes: &[u8]) -> Result<GgufArtifact, GgufError>` where `GgufArtifact { tensors: Vec<ModelTensorMetadata>, metadata: BTreeMap<String, GgufMetadataValue> }` (`GgufMetadataValue` a small generic enum over GGUF's typed KV value kinds -- string/int/float/bool/array -- not a `magnetar-runtime` type, since this is format-specific key-value data with no generic Model Artifact equivalent yet).

Assembling a full `ModelManifest` from a `SafetensorsArtifact`/`GgufArtifact` plus externally-known identity/architecture metadata is the caller's job (today: test fixtures and future `Model Loading` wiring, out of this change's non-goal scope). This keeps both parser crates honest about what a weight file alone can and cannot prove, and avoids inventing manifest-identity semantics (digest, revision, architecture family) inside a format parser that has no authority over them.

*Alternative considered:* have each parser return a fully-populated `ModelManifest` with placeholder/synthesized identity fields. Rejected -- it would either fabricate identity data the file doesn't contain, or push `ModelArtifactId` construction into the parser, which then needs to know about Runtime-level identity policy it has no business knowing (mirrors why Reference CPU's Kernel bodies don't decide Provider selection).

**Overflow and bounds safety: checked arithmetic throughout, matching the existing `reference_cpu.rs::host_tensor_element_count` pattern.** Every offset, length, and dimension read from file bytes is `u64` from untrusted input; every size computation (element count from shape, byte size from element count and dtype width, end offset from start and length) uses `checked_mul`/`checked_add` and rejects on `None` rather than wrapping, and every `u64 -> usize` narrowing uses `try_from` rather than `as` (the same 32-bit-target truncation concern `host_tensor_element_count`'s doc comment already documents, relevant here since these crates also build for `wasm32-unknown-unknown`). Declared tensor byte ranges are validated against the actual remaining file length before any slice indexing.

**Overlapping tensor byte ranges are rejected, not permitted.** Upstream `safetensors` hardened its reference parser to reject overlapping tensor storage after a disclosed vulnerability class (a maliciously crafted header claiming overlapping regions can be used to construct type-confused aliased views). Both parsers here reject any two tensors whose declared `[start, end)` byte ranges overlap, full stop -- no attempt to distinguish "legitimate" intentional aliasing (e.g. tied embeddings) at the format layer. `magnetar-runtime`'s own tied-embedding handling (`TensorAliasing::MayAlias`, seen in `graph_builder_capability.rs`) already exists at the *graph edge* level, not the *file byte range* level, so this loses nothing: a model with tied embeddings simply appears in the file as one physical tensor, referenced by two logical names at a higher layer, not as two overlapping byte ranges.

**Fuzzing runs outside normal CI; the corpus regression suite runs inside it.** `cargo-fuzz`/`libfuzzer-sys` targets require a nightly toolchain and are not something `cargo test` on stable can execute, so a `fuzz/` directory with one target per crate (`formats/safetensors/fuzz/fuzz_targets/parse.rs`, same for GGUF) is added for local and periodic (not per-PR) fuzzing, matching common Rust practice. Every crash/hang libfuzzer finds during that offline fuzzing gets its input byte sequence checked into a `tests/corpus/` directory and replayed by an ordinary `#[test]` function (`for entry in read_dir("tests/corpus") { assert!(parse(&entry).is_err()) }` or equivalent, asserting a structured error, never a panic) -- that regression suite *does* run in normal `cargo test` / the existing `submodule-integration` CI job, with zero nightly-toolchain requirement. The corpus starts non-empty at initial implementation (truncated headers, out-of-range offsets, overlapping ranges, integer-overflow-inducing dimensions, invalid UTF-8 in string fields, wrong magic bytes) even before any fuzzer has run, so the safety guarantee is real from the first commit, not contingent on fuzzing having been run yet.

**Dependency direction and crate shape mirror `providers/cpu`.** Each format crate's `Cargo.toml` gets a path dependency on `magnetar-runtime` (for `ModelTensorMetadata`/`ModelDType`/`ModelQuantization`/`ModelQuantizationFormat`), an explicit `[workspace]` table (required for every submodule per the bug task group 14/15 found and fixed this session), and a committed `Cargo.lock`. `magnetar-runtime` gains no new dependency; the existing task-16.4 static guard (already trivially true today) gets extended to remain true once these crates have real content, by asserting via `cargo tree`/manifest inspection (exact mechanism a task, not decided here) that neither crate appears in `magnetar-runtime`'s own dependency graph.

## Risks / Trade-offs

- [Risk] GGUF's KV metadata section is large and loosely specified in practice (informal community conventions, not a versioned schema) -- a parser strict about unknown keys would reject real-world files; a parser permissive about them risks silently accepting garbage. → Mitigation: unknown/unrecognized metadata keys are preserved verbatim in `GgufArtifact::metadata` (opaque to the parser) rather than rejected; only the tensor-info section (name/shape/dtype/offset, which *is* strictly specified) is validated strictly. This mirrors `model-format-roadmap`'s existing "Format Normalization Preserves Source Annotations" requirement (`torch_dtype`-style fields preserved as source metadata, not silently forcing policy).
- [Risk] Real-world GGUF/Safetensors files can be many gigabytes; a parser that reads the whole file into memory before validating anything defeats the overflow/bounds-safety goal by allocating first and checking second. → Mitigation: parse headers/metadata (small, bounded) fully in memory, but treat tensor byte data as a set of validated `(offset, length)` ranges into the caller-supplied byte source rather than copying it during parsing -- the exact I/O shape (mmap vs. caller-provided slice vs. reader trait) is an implementation task, not decided here, but "validate the range before any data movement, never copy speculatively" is the fixed design constraint regardless of which I/O shape tasks.md ends up choosing.
- [Risk] This change's scoped-down GGUF quantization support (`Q4K`/`Q5K`/`Q8` only) means real-world GGUF files using other common quant types (`Q4_0`, `Q6_K`, etc.) will be rejected outright once this ships, which could read as "GGUF support" being broader than it is. → Mitigation: the rejection is structured and explicit (`gguf-quantization-unsupported`, naming the actual `ggml_type` found), not a silent failure, and both the proposal and this design call the limitation out by name rather than letting "GGUF support" imply full coverage.
- [Trade-off] Returning a narrower `SafetensorsArtifact`/`GgufArtifact` instead of a full `ModelManifest` (see Decisions) pushes manifest-assembly work onto whatever calls these parsers, rather than giving a one-call "parse this file into a loadable Model Artifact" experience. Accepted deliberately -- see Decisions for why a parser fabricating identity metadata it cannot know is worse than an honest, narrower contract.
